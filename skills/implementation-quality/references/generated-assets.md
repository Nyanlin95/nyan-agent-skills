# Generate assets from text

Prefer text-authored assets when reviewable source, repeatable generation, or systematic variation materially helps the requested artifact. Preserve established native authoring tools when they better support visual or audio quality. Do not replace an asset pipeline merely to make everything code.

1. Define the authored source, generated output, and canonical style or palette owner.
2. Reuse an existing format and generator before adding a custom one.
3. Make generation reproducible with explicit versions, configuration, and seeds where needed.
4. Validate malformed input and the project's relevant output constraints.
5. Render or play the generated artifact in its actual consumer.

Check legibility, visual or audio fidelity, localization, and delivery size where affected. Keep source and output ownership explicit; do not hand-edit generated files. Route build-budget enforcement to the existing gate rather than creating a parallel pipeline.

Adapted from the [tibo.dog development thread](https://x.com/poteto/status/2117043478140276847), which used text-authored sprites and synthesized music; choose formats for the current artifact.
