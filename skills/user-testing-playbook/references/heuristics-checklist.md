# Heuristics checklist (use after sessions to catch what the personas did not hit)

Use as a prompt for "did we see this?", not as a replacement for sessions. Cite a screen and evidence for each hit.

## Ten usability heuristics (Nielsen)
1. Visibility of system status: does it show loading, saving, success, failure?
2. Match with the real world: words and icons a user knows?
3. User control and freedom: undo, cancel, back, clear exits?
4. Consistency and standards: same thing looks and works the same everywhere?
5. Error prevention: confirmations on risky steps, safe defaults, inline validation?
6. Recognition over recall: options visible, not remembered?
7. Flexibility and efficiency: shortcuts, search, bulk actions?
8. Aesthetic and minimal design: only relevant information?
9. Help users recognise, diagnose and recover from errors: plain message, a way forward?
10. Help and documentation: findable, short, task-based?

## Extra checks
- First 5 seconds: is it clear what this is and who it is for?
- Empty, loading, error, offline, full and expired states all designed?
- Forms: labels, required marks, error placement, keeps input after an error, correct keyboard type on phones.
- Targets and layout: tap targets at least 44 px, no horizontal scroll at 360 px wide, nothing cut off at 200% zoom.
- Keyboard: logical Tab order, visible focus, Escape closes dialogs, no trap.
- Accessibility basics: text alternatives, labels for controls, contrast, not only colour for meaning, respects reduced motion.
- Performance: layout shifts, long blank waits, janky scroll.
- Trust: pricing shown early, no hidden fees, clear opt-outs, no fake urgency, privacy choices real.
- Copy: no dev wording, no dead-end errors, consistent names.
- Recovery: refresh, Back and reopen keep the user's place and data.
